# 03 · 数值框架与占位约定

> 前置：C5「先按已定稿部分开工，缺口留占位标『未判定』」；本轮新增 D-2026-11-04-02（Q1–Q11）。
> 本文只定**数值长什么样、从哪来、缺了怎么标**，**不填任何一个平衡数值**。
> 一句话现状：**结构常量基本齐了，平衡数值仍然几乎全缺。** Q1–Q11 答完的是「规则和形状」，不是具体数值。

## 一、两类数值要分开看

| 类别 | 是什么 | 现状 |
|---|---|---|
| **结构常量** | 数量、档位、上限、坐标、分辨率这类「有几个／到哪为止」 | 大部分已定，可直接进配置表 |
| **平衡数值** | 经验曲线每一级、伤害、成功率、掉落率、属性加成这些「具体多少」 | **几乎全缺**，只有老玩家能补 |

把两者混起来最危险：看到「150」「10 部位」「每级 5 点」容易以为数值已经齐了，
其实连一条伤害公式、一级要多少经验都还没有。下面分开列。

## 三、配置表通用 schema（每个数值条目长这样）

```json
{
  "id": "level_exp_42",
  "value": null,
  "status": "未判定",
  "source": null,
  "unit": "exp",
  "note": "1–150 经验曲线，形状已由 Q7 定为前平后陡，逐级数值待补"
}
```

已定值的样子：

```json
{
  "id": "level_cap",
  "value": 150,
  "status": "已定",
  "source": "docs/00 审核定稿 · Q7",
  "unit": "level",
  "note": ""
}
```

**字段规定**

| 字段 | 规定 |
|---|---|
| `value` | 数值本身；未知时**必须是 `null`** |
| `status` | 只能是 `已定`／`未判定`／`确实没资料` 三选一 |
| `source` | 必填到能追溯：文档名＋条目号，或 Q／N 编号。`未判定` 时填对应 Q／N 编号 |
| `unit` | 单位；单位本身没定时填 `"待定"`，不许默认套用 |
| `note` | 口径说明、歧义、待补线索 |

`source` 写「用户判定」的，必须同时能追到 `docs/03` 的决策条目
（本轮为 `D-2026-11-04-02`），不许只写「用户说的」。

`status = 确实没资料` 只用于用户明确判过的 A2（字体族／描边参数）与 A5（UI 交互态）；
这两类允许用自定但一致的默认样式，代码里必须标「非考据还原」，**不许伪装成考据结论**。

## 四、占位约定（C5 的核心，硬性）

1. **禁止猜值**：不知道就 `null`，不许填 0、1、100 之类「看起来合理」的数。
   `0` 在很多系统里是合法值（免费、无消耗），用它冒充未知会造成静默错误。
2. **禁止用注释代替状态**：不能只在代码里写 `// TODO 待补`，配置表里必须同时有 `status: 未判定`。
3. **运行时遇到 `未判定` 怎么办 → 待确认**：
   推荐做法是「临时生成一个中性占位值让流程跑通，但**不写回配置表**、界面与日志显式标注『占位』」。
   这条属于实现约定，先列为草案，**等用户确认**（见 `docs/04` Q22 附注）。
4. **占位不参与验收**：「准」阶段判定通过的条件是「不存在来源不明的数值」，
   而不是「占位都被填上了」。占位可以合法存在，但必须一眼看得出是占位。
5. **形状 ≠ 数值**：Q7 那种「曲线前平后陡」属于形状约束，写进 `note` 或单独的结构字段，
   **不许据此生成一条看起来合理的经验表**。

## 六、数值分层与叠加顺序（结构草案，未定稿）

```
职业基础 → 等级成长 → 属性点分配 → 装备 → 翅膀 → 套装档 → 临时 buff → 最终属性 → 战斗结算
```

这个**顺序本身还没确认**：原版可能是乘法叠加、可能是加法、也可能套装在装备之前算。
在 N6／Q14 答完前，只把顺序画成可调整的管道，不写死公式。
`docs/design/02` 的 M1→M2→M3 依赖方向与此一致：属性重算由 M1 统一出，其他系统只提供加成项。

## 七、来源标记规则（防「数值自己长出来」）

每个进 `_archive/legacy-web-layout/data/` 的值必须满足以下之一：

- 能追到 `docs/design/00-事实基线与玩法口径.md` 的某条确定值；
- 能追到 `docs/decisions/00-审核定稿与决策记录.md` 的某条用户判定；
- 能追到 `docs/decisions/03-决策记录.md` 的某条决策（本轮为 `D-2026-11-04-02`）；
- 能追到 `docs/decisions/04-待确认问题.md` 的某个 Q／N 编号，且 `status` 为 `已定`（用户答完之后）。

**追不到的值不许存在。** 这条是「准」阶段验收时逐表扫描的检查项。

另：用户口径与考据资料冲突时，按「用户判定 > 网络资料 > 考据推理」压，
**生效值只有一个**；资料原文留痕在 `docs/04` 第六节，**不进配置表**，
也不许以「备注」名义写进 `note` 变成第二套口径。
