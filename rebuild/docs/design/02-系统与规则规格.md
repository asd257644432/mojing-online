## 一、全局规则（所有系统共用，优先级最高）

### 1. 状态所有权
`M10 state-authority` 是**唯一**持有游戏状态的地方。M1–M9 只描述规则，不各自存一份玩家数据。
`_archive/legacy-web-layout/client/` 不持有游戏状态，只发意图、只收状态快照。这条现在定死，将来加多人时把 M10 整体搬到 `_archive/legacy-web-layout/server/` 即可。

### 2. 单向依赖
`_archive/legacy-web-layout/client/ → _archive/legacy-web-layout/domain/ → _archive/legacy-web-layout/data/`，下层绝不反向。考据资料和文档谁也不依赖、谁也不被依赖。
界面不许直接改数值，配置表不许引用界面路径。

### 3. 权威判定
伤害结算、掉落、交易、任务进度一律走 `_archive/legacy-web-layout/domain/`。客户端可以本地预测表现，但**结果以 M10 为准**。
单机阶段存档可本地读写，但「结果性」数值不得由 `_archive/legacy-web-layout/client/` 直接写回。

### 4. ID 引用，不写路径
配置里写 `wing_appearance_id: wing_t3`；`_archive/legacy-web-layout/domain/` 里不出现 `_archive/legacy-web-layout/public/img/...`；
资源路径只由 `_archive/legacy-web-layout/client/` 的解析层拼。`assets/` 与 `_archive/legacy-web-layout/public/` 的关系由构建脚本维护。

### 5. 逻辑节拍
固定步长逻辑 tick，与渲染帧解耦；渲染 60／30 帧可调（A3）。
**切换方式是手动还是自动，未定 → Q20。**

### 6. 规则优先级（冲突时照这个压）
```
用户判定（docs/00） > 决策记录（docs/03） > 事实基线（docs/design/00）
> 配置表（_archive/legacy-web-layout/data/） > 代码默认值
```
代码默认值永远排最后，且只允许出现在「用户明确说确实没资料」的项（A2 字体、A5 UI 交互态）。
本轮 Q5／Q9 与考据资料的冲突，就是按这条压的：**生效口径只有用户这一份**，
资料原文留痕、不进配置表。

### 7. 变更规则
「同一个事实只有一个家」：改一个数值只改 `_archive/legacy-web-layout/data/` 一处；改一条规则只改本文件一处，
并同步更新受影响的 Q／N 编号状态。不允许在多个文档里各写一份略有不同的说法。

### 8. 规则生效范围
本文所有规则适用于**复刻版**。原版有什么、但被用户判定剔除的（商业化、活跃度、六国），
在这里一律不产生系统、不产生规则。
Q1B／Q2B／Q3B 保留的是**界面**，不是原版的多人玩法；空壳不产生状态、不产生数据。

## 二、M1–M10 系统契约

### M1 `progression` 成长
- **持有什么**：等级、经验、自由属性点分配、转职状态（翅膀 3 种之一）、翅膀外观 id。
- **输入**：M5 发放经验、M3 装备变更、M10 存档载入。
- **输出**：等级变化、属性点重算、转职事件。
- **已定规则**：上限 150；转职后重置自由属性点；转职＝翅膀 3 种（C7），
  名称**天使／恶魔／精灵**（Q9 查资料）；翅膀影响外观并加一点属性；
  **翅膀获取＝转职、转职消耗紫晶**（Q9）；
  **属性 5 项（力量／敏捷／智力／精神／体质）、每级 5 点**（Q6）；
  **1–150 经验曲线前段平滑、后段变陡**（Q7，只定形状，不是数值）。
- **未定**：5 点是属性点还是技能点、能否洗点／单项上限／职业初始值 → **N3**；
  1–150 **逐级经验数值** → 仍未定，不许由「形状」反推出一条曲线；
  转职等级门槛、紫晶产出、三种翅膀各自加成与进阶档数 → **N2／N4**。

### M2 `combat` 战斗
- **持有什么**：当前目标、技能冷却、战斗状态（进行／结算／死亡）。
- **输入**：M9 的放技能意图、M4 的怪物实体、M1 的属性。
- **输出**：伤害数值、飘字事件、死亡事件、掉落请求。
- **已定规则**：即时战斗；自动战斗／一键挂是同一套；快捷栏 1–8、**可拖放**（Q8）；
  暴击飘字存在（图证）；
  **命中率／闪避率／暴击率三项；暴击分物理／魔法两套（物暴↔敏捷、魔暴↔精神），暴击＝双倍伤害**
  （`D-2026-11-15-01` 覆盖 Q4 的「不分物理魔法」）；
  **三档复活：免费回城／银币原地 30% 血／金币原地 100% 血**（Q5）；
  **自动战斗全自动：选怪＋放技能＋拾取＋补血**（Q11「可以」，按 A 理解，待用户一句话确认）。
- **未定**：基础伤害公式、属性→伤害换算、要不要做威胁值／仇恨 → **N6**；
  两档原地复活的价格／冷却／次数限制、第三档金币用绑定还是非绑定 → **N1**；
  技能数量／冷却／MP／技能点 → **N7**。

### M3 `inventory-equipment` 背包装备
- **持有什么**：物品实例、10 部位当前装备、套装件数、货币数量。
- **输入**：M2 掉落请求、M8 交易结果、M5 任务奖励。
- **输出**：属性重算请求（给 M1）、装备外观 id（给 `_archive/legacy-web-layout/client/`）。
- **已定规则**：10 部位；5 职业各一套；3／6／8／10 件四档套装；整套换装（A8）；
  星空碎片 ×15 兑换价；需求级别 120～128；金／银／铜＋绑定金。
- **未定**：强化／改造／镶嵌成功率与上限 → **Q13**；星空碎片兑换的具体物品、套装逐档加成 → **Q14**；
  货币换算与非绑定判定细节 → **Q15**。

### M4 `world-navigation` 世界寻路
- **持有什么**：当前地图 id、坐标、传送阵状态、副本实例与当日次数。
- **输入**：M9 的点击／寻路意图、M5 的任务目标。
- **输出**：位置变化、切图事件、实例进入。
- **已定规则**：地图有边界、触碰传送阵切图（A7）；单图内 A*，不做跨图无缝路径；
  8 向；10 级前遗迹之岛／30 级前沐光平原／之后生命之境；
  **副本每个每天各 2 次**（Q10）；**免费回城复活点**（Q5）。
- **未定**：传送阵解锁的等级门槛 → **N2**（与转职门槛绑定）；
  组队分配的距离阈值、单机空壳下队友来源 → **N5**。

### M5 `quest` 任务
- **持有什么**：任务进度、`0/x` 计数、已交付集合。
- **输入**：M2 击杀事件、M3 拾取事件、M4 到达事件。
- **输出**：经验／物品奖励（给 M1／M3）、任务追踪状态（给 `_archive/legacy-web-layout/client/`）。
- **已定规则**：主线／日常两链，带 `0/x` 计数；核心闭环里「点任务名自动寻路」；
  任务发放的经验按 **Q10 组队规则**（按距离判定有份队友后平分）计算。
- **未定**：主线是否强制线性、日常重置时间、能否放弃重接 → **Q16**；
  距离阈值与单机空壳下队友来源 → **N5**。

### M6 `social-nation` 社交国家
- **持有什么**：所属国家、组队成员、公会／好友／邮件、聊天频道、国战状态。
- **输入**：M9 的社交操作、M10 的状态快照。
- **输出**：组队加成（若有）、国战事件。
- **已定规则**：三国（明土／水月／风火）；组队 6 人（自己 + 5 名队友，`D-2026-11-15-02` 覆盖 A10 的 5 人）；8 个聊天频道；
  「万人混战」只是宣传概念，**不设单场人数上限**（C6）；
  **Q1B：MMO 外壳界面全保留、没有真实玩家数据**；**Q3B：国战只留入口、空壳**。
  空壳面板**不产生 `Command`、不向 M10 提交变更，也不许造假数据填界面**
  （边界见 `docs/architecture/02` 第三节）。
- **未定**：空壳界面的空状态表现属「确实没资料」，按自定样式处理并标「非考据还原」；
  **单机没有真实队友，组队经验分配怎么验** → **N5**。

### M7 `activity` 活动
- **已按用户判定裁剪为空**：不做活跃度、签到奖励、抽奖、转盘、押镖、在线奖励。
- **保留**：副本每日次数这类非商业化频次规则，归 M4 管理。
- **无未定项**。

### M8 `economy` 经济
- **持有什么**：货币账、绑定标记、拍卖行挂单。
- **输入**：M2 掉落、M3 物品变更、M5 奖励。
- **输出**：交易结果、货币变动。
- **已定规则**：金／银／铜三级；非绑定即可交易；拍卖师两处坐标；**不做任何商业化**（Q2）；
  **Q2B：拍卖行保留界面、没有交易对象**，不产生挂单数据；
  **Q5：复活第三档用金币**（绑定／非绑定未定 → N1）；
  **Q9：紫晶为转职消耗物**（产出未定 → N2）。
- **未定**：货币换算比例、绑定金产出、手续费 → **Q15**；紫晶产出 → **N2**。

### M9 `input-hud` 输入与 HUD
- **持有什么**：**不持有游戏状态**，只有键位映射、面板开关、选中目标等纯视图状态。
- **输入**：鼠标／键盘。
- **输出**：意图（给 M1–M8）、状态渲染请求。
- **已定规则**：1920×1080 等比缩放；默认原味键位＋可切现代；双排 8 格快捷栏、7 功能按钮、8 聊天频道、HUD 九宫格；
  **快捷栏可拖放**（Q8，用户判定，非考据）；**自动战斗全自动开关**（Q11）；
  **Q1B／Q2B／Q3B 的空壳面板只画界面与空状态，不造假数据**。
- **未定**：1–8 之外的原味键位与移动方式 → **Q17**；缩放策略细节 → **Q19**；
  拖放动画／冷却遮罩按 A5「确实没资料」用自定样式 → **N7**。

### M10 `state-authority` 状态权威
- **持有什么**：**全部**游戏状态、tick、存档。
- **输入**：所有系统的状态变更请求。
- **输出**：状态快照（给 `_archive/legacy-web-layout/client/`）、存档读写。
- **已定规则**：单机优先；权威判定归 `_archive/legacy-web-layout/domain/`；IndexedDB 存档（C4）。
- **未定**：存档位数与自动存档时机 → **Q18**；存档 schema 版本迁移策略 → 本轮给推荐，见 `docs/architecture/02`。

## 三、核心闭环的规则化描述

```
点任务名 → M5 给目标 → M4 寻路 → 点怪 → M9 发意图 → M2 即时结算
→ 飘字／掉落 → M3 拾取 → M5 交付 → M1 升级加点 → M3 整套换装／套装档
→ 到等级门槛 → M4 触碰传送阵切图 → 副本（每日次数）
```

每一步都必须能回答「谁改了状态、改了哪一处」。Q1–Q11 已把主干规则定下来；
若某一步仍需要未定规则（**N1／N5／N6／N7** 等），
就先以**占位规则**跑通流程，不填具体数值 —— 占位约定见 `docs/design/03-数值框架与占位约定.md`。

## 四、验收规则（对应「先像 → 再准 → 再好玩」）

- **像**：对照截图验 HUD、视角、比例、配色、8 向、整套换装、传送阵切图。不看数值。
- **准**：本文每条「已定规则」逐条跑通；每条「未定」必须能在配置表里查到 `status: 未判定`，
  而不是查到一个看起来合理的数。
- **好玩**：实机试玩，验 Q11 自动战斗行为、帧率档位、反馈节奏。

**判定「准」阶段通过的一个硬条件**：`_archive/legacy-web-layout/data/` 里不存在任何来源不明的数值。
每个值要么来自 `docs/design/00`，要么标 `未判定`。
空壳界面不参与「准」阶段的玩法验收，只验「界面在、且没有假数据」。
