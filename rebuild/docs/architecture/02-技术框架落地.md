## 一、技术栈定稿与各自边界

| 层 | 定的东西 | 只负责 | 明确不负责 |
|---|---|---|---|
| 渲染 | **PixiJS**（C1） | 斜 45° 地图、8 向精灵、图集、特效、y-sort | 不画 DOM 面板、不存游戏状态 |
| UI | **DOM/CSS 覆盖画布**（C2） | HUD 九宫格、聊天框、任务追踪、各类面板、文本输入 | 不持有游戏状态、不直接改数值 |
| 语言／构建 | **TypeScript ＋ Vite**（C3） | 类型约束、配置表校验、构建产物 | 不含运行时业务逻辑 |
| 存档 | **IndexedDB**（C4） | 存档位、状态快照、版本迁移 | 不判权威结果、不做交易校验 |

DOM 层与 Canvas 层**必须挂在同一个缩放容器里**，否则窗口一缩放，点击坐标就会和画面对不上（这是 C2 的已知代价）。

## 三、数据流（预留多人的关键设计）

```
用户操作
  → _archive/legacy-web-layout/client/input 生成 Command（纯数据、可序列化、不含状态）
  → _archive/legacy-web-layout/platform/event 投递
  → _archive/legacy-web-layout/domain/M* 校验并执行，向 M10 提交状态变更请求
  → M10 更新状态，产生 Snapshot（纯数据、可序列化）
  → _archive/legacy-web-layout/client/ui + _archive/legacy-web-layout/client/render 只读 Snapshot 渲染
```

**为什么这么定**：`Command` 和 `Snapshot` 都是可序列化的纯数据。将来加多人时，
只要把 `_archive/legacy-web-layout/platform/event` 的本地投递换成 WebSocket 收发、`M10` 整体搬到 `_archive/legacy-web-layout/server/`，
`_archive/legacy-web-layout/domain/` 和 `_archive/legacy-web-layout/client/` 的业务逻辑不用重写 —— 这就是 Q1「先单机、架构预留多人」的具体落地。

三条现在就要守住的边界：

1. `_archive/legacy-web-layout/client/` 只发意图、只收快照，**不持有游戏状态**；
2. 伤害／掉落／交易／任务进度的结果一律由 `_archive/legacy-web-layout/domain/` 判，客户端可以预测表现但不改结果；
3. 客户端**不得直接写回结果性数值**。

### 空壳面板的边界（Q1B／Q2B／Q3B，D-2026-11-04-02）

用户定了：公会／好友／邮件／8 个聊天频道／国战／拍卖行**界面全保留，但没有真实玩家数据**。
落到本文件就是下面五条，写代码前不用再讨论：

- `_archive/legacy-web-layout/client/ui` 可以画面板、标签页、空列表和「暂无数据」的空状态；
- **不许造假的玩家、挂单、聊天记录、国战战报**去把界面填满 ——
  那是凭空发明数据，跟 C5「禁止猜值」是同一类错误，只是发生在界面上；
- 这些面板**不产生 `Command`、不向 M10 提交状态变更请求**，只是只读快照的展示位；
- `_archive/legacy-web-layout/domain/` 里 M6／M8 的规则继续存在、但暂时没有输入源；`_archive/legacy-web-layout/server/` 继续保持为空，
  **不因为要显示空壳就引入多人服务**；
- 将来从单机切多人，只要给这些面板接上真实数据源即可，界面不用重写 ——
  这正是本节 Command／Snapshot 设计预留的口子。

## 四、逻辑节拍与帧率

- 逻辑用**固定步长 tick**，渲染帧 60／30 可调（A3），两者解耦。
  推荐逻辑 tick 为 1/60 秒：这样切到 30 帧渲染时战斗不会跟着变慢。
- tick 内只跑 `_archive/legacy-web-layout/domain/` 规则；`_archive/legacy-web-layout/client/` 只在帧里读快照渲染。
- **60／30 是手动切还是按性能自动 → 未定，Q20**。
- 渲染帧率档位与逻辑步长是两个概念，配置表里分开两个字段，不许合并。

## 五、存档结构（IndexedDB 草案）

```
db        mjol-save
store     saves   key = slotId
                  value = { schemaVersion, savedAt, snapshot, label }
store     meta    key = 'lastUsedSlot'
```

- `snapshot` 直接序列化 M10 的状态；**不另存一份 UI 状态**。
- 读档时若 `schemaVersion` 落后，走迁移函数链逐级升级；迁移失败**拒绝读档并保留原档**，不许覆盖。
- 存档位数与自动存档时机 → **未定，Q18**。
- 单机存档用户能改，这阶段无所谓；将来若有交易或排名，必须服务端权威＋校验（见 `docs/architecture/01` 第五节）。

## 六、资源管线

```
assets/（原创重绘源文件）
  → _archive/legacy-web-layout/platform/build 生成图集 + manifest.json
  → _archive/legacy-web-layout/public/（浏览器直接加载）
  → _archive/legacy-web-layout/client/resource 按 id 解析路径、按场景按需加载 + 进度条
```

- `_archive/legacy-web-layout/domain/` 里只写 `wing_appearance_id: wing_t3`，**绝不出现** `_archive/legacy-web-layout/public/img/...`；
- `_archive/legacy-web-layout/public/` 里每个文件都必须能由 `assets/` ＋构建脚本重新生成，手改 `_archive/legacy-web-layout/public/` 视为违规；
- 合入资产前跑哈希比对，比对范围含 `resources/originals/network/`、`resources/originals/user/`、`resources/reference-views/sheets/`、`resources/reference-views/zoom/`，见 `docs/art/01`。

- 设计基准 **1920 × 1080**（A1／D15）；Canvas 与 DOM 覆盖层共用同一缩放容器。
- 等比缩放的具体策略（留黑边／拉伸／UI 自适应重排）→ **未定，Q19**。
