# 16 · 魔镜Online Godot 复刻施工总案

> **2026-11-13 拍板记录（取代旧口径，旧文档不删不改）**
>
> 1. 技术路线改 **B：Godot 4 导出 Web**，C1–C4（PixiJS / DOM 面板 / TS+Vite / IndexedDB）作废。
> 2. 暴击**分两套**：物理暴击、魔法暴击；命中仍共用一套，暴击伤害 **2 倍**。
> 3. 复活**三档**：免费回城 / 绑定银币原地 30% 血（便宜）/ 非绑定银币原地满血（更贵）。
> 4. 每级 5 点 **加属性**，不加技能点；技能靠技能书。
> 5. 转职**只按翅膀三形态**（天使 / 恶魔 / 精灵），不采信「六大二转职业」。
> 6. 等级上限 **150**；组队上限改 **6 人**（自己 + 5 名队友）。
> 7. **天赋要做**；资料只有「12 系」这个数字，系名与节点名一律占位，不编。
> 8. **暂不做存档**；启动即新档，状态结构保持可序列化，以后补一层即可。
> 9. 货币 **百进制**：1 金 = 100 银，1 银 = 100 铜；银、铜显示上限 99，自动进位。任务奖励进**绑定**账户，出售所得进**非绑定**账户。两档原地复活分别扣绑定 / 非绑定银币。
> 10. 缺数值可以**先填合适值**，但必须挂 `推定` 牌子，不得冒充考据。

本文只回答「按 Godot 怎么一步步做出来」。游戏内容口径仍以事实基线、系统规则、核心循环三份文档为准；冲突时以 2026-11-13 这十条为准。

---

## 一页看懂

- **做什么**：把 2011 年三国版《魔镜Online》复刻成浏览器里能玩的单机版，1920×1080，六职业，150 级，即时战斗。
- **不做什么**：商业化全套、活动玩法、六国旧版、真实多人、假数据填充。
- **怎么走**：九段施工，每段都能单独打开验收；上一段没过，不进下一段。
- **最大三个坑**：没有可行走地图底图、没有 8 向行走帧、天赋只有数字没有内容。这三件事不解决，后面全是空转。

## 二、技术底座

### 2.1 引擎与语言

| 项 | 定什么 | 为什么 |
|---|---|---|
| 引擎 | Godot 4.x 最新稳定版 | 场景、动画、寻路、UI 全内置，省掉自研 |
| 语言 | GDScript 2.0，全量静态类型 | 与引擎贴得最紧；C# 的 Web 导出支持不完整，不赌 |
| 渲染 | 2D，基准 1920×1080，等比留黑边 | 与视觉规格一致，窗口变化不重排 UI |
| 帧率 | 逻辑固定 60Hz，画面 60 / 30 可切 | 逻辑与画面解耦，掉帧不影响判定 |
| 导出 | Web（WebAssembly） | 目标就是浏览器点开就玩 |

**工程纪律（照做，不讨论）**

- 所有变量、参数、返回值写类型；不写 `var x =`。
- 节点引用只在 `_ready()` 里用 `@onready` 取一次，禁止运行中反复按路径找节点。
- 节点之间往上通信一律用信号，信号名 `snake_case`，参数带类型；子节点不许 `get_parent()`。
- 自动加载只留三个：`GameState`（唯一状态）、`DataDB`（配置表）、`EventBus`（跨场景事件）。其他一律不许加。
- 节点删除只用 `queue_free()`。

### 2.2 项目目录

```
project.godot
scenes/          场景：main / world / entities / ui
scripts/         脚本：core / domain / ui / tools
resources/       需要编辑器里看的少量资源（主题、字体、输入映射）
_archive/legacy-web-layout/data/            JSON 配置表（唯一事实源）
assets/          图、音、字体（成品，可直接打包）
art-source/      还要再改一刀的源文件（不进包）
_archive/legacy-web-layout/tests/           数据校验与规则单测
```

与旧 A 方案的区别：不再分 `client / domain / platform / public` 四层，改成 Godot 的「场景 / 脚本 / 数据 / 资源」。**逻辑分层保留**：`scripts/domain/` 只算数不碰节点，`scripts/ui/` 只显示不改状态。

### 2.3 数据：JSON 是唯一源

- 所有配置表放 `_archive/legacy-web-layout/data/`，UTF-8，一个事实只出现一次。
- 启动时 `DataDB` 一次性读进内存字典，运行时只读，不写回。
- 编辑器里**不**再维护一份 `.tres` 数值，避免两个家。
- 每条数值六个字段：`id / value / status / source / unit / note`；`status` 只允许 `已定 / 推定 / 未判定 / 确实没资料`。
- 「推定」的判定标准：为了能跑而填、没有考据支撑。填了就填了，但必须能被一条命令扫出来。

首批表：`classes`、`attributes`、`level-curve`、`skills`、`talents`、`items`、`equipment`、`sets`、`monsters`、`maps`、`quests`、`npcs`、`currency`、`ui-layout`。

### 2.4 场景与渲染

| 层 | 做法 |
|---|---|
| 根 | `Main` 场景，挂缩放容器，固定 1920×1080 |
| 世界 | `World` 节点下按地图挂 `MapRoot`；一张图一个场景，切图就换场景 |
| 地图 | 整张底图用 `Sprite2D`，**不用 TileMap**（没有瓦片素材）；碰撞用 `CollisionPolygon2D` 手画；遮挡靠 `y_sort_enabled` |
| 角色 | `CharacterBody2D` + `AnimatedSprite2D`；8 向用 8 组动画名 `walk_n / ne / e / se / s / sw / w / nw` |
| 相机 | `Camera2D` 跟随，限制在地图边界内 |
| 特效 | `AnimatedSprite2D` 或 `GPUParticles2D`；先做 3 个通用特效：命中、暴击、升级 |

### 2.5 战斗与寻路

- 伤害、命中、暴击、掉落、任务计数全部在 `scripts/domain/` 里算，节点只负责播动画和飘字。
- 战斗节拍走 `_physics_process`（固定 60Hz），不用 `_process` 做判定。
- 寻路用 `NavigationRegion2D` 烘焙 + `NavigationAgent2D`，只在单图内，不跨图。
- 自动战斗是「状态机 + 定时器」：找最近怪 → 走到攻击距离 → 放技能 → 捡东西 → 血低吃药。与手动共用同一套技能接口。

### 2.6 UI

- 全部用 `Control` + `Theme`，一个 `CanvasLayer` 装 HUD，另一个装弹窗。
- 九宫格面板用 `NinePatchRect`，边距按已切好的 3 倍图实测值。
- 字体：思源黑体子集（常用 3500 字 + 数字符号），避免整包字库把 Web 包撑大。
- 面板只读 `GameState` 的快照，不许直接改数值；所有操作发「意图」给规则层。

### 2.7 存档

本期不做。启动给固定初始角色，关掉即重来。
但所有状态结构按「可 JSON 序列化」设计：以后加存档，只补一个读写层，不动规则。

### 2.8 Web 导出

- 部署要开两个跨源响应头（COOP / COEP），否则多线程版起不来；静态托管默认没有，要单独配。
- 首屏要有加载条；贴图压缩、音频转 ogg、字体子集三件事必须做，否则包体失控。
- 目标：首次加载 ≤ 8 秒（本地千兆），包体 ≤ 30 MB。
