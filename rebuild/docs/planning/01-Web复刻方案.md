## 一、这次到底要做什么

**不是移植，是照着截图和行为描述重做** —— 原版 Flash 没有源码可用。
目标是一个能在 PC 浏览器里跑起来的《魔镜Online》复刻版，先做到「看着像、玩着是那套」，
再逐步对齐规则数值，最后调手感。

用户拍板的边界（不再讨论）：

| 维度 | 定稿 |
|---|---|
| 范围 | **单机优先**，架构预留多人 |
| 商业化 | **完全不做** |
| 平台 | **PC 为主**，基准 **1920×1080** |
| 版本 | **三国（明土／水月／风火）**，等级上限 **150** |
| 操作 | 默认原味 Flash 键位，可切现代键位 |
| 验收 | **先像 → 再准 → 再好玩** |
| 考据图 | 只作验收参照，不得当贴图 |

## 二、技术选型（这里请你拍板，我没替你定）

每个都给推荐和代价，选完我再落 `package.json` 和代码骨架。

| 选择点 | 方案 A（推荐） | 方案 B | 代价差别 |
|---|---|---|---|
| 渲染 | **PixiJS**（WebGL／Canvas 2D 自动降级） | 纯 Canvas 2D 自绘 | A 自带批渲染、图集、滤镜、精灵帧，省事；代价是引入依赖、包体变大。B 零依赖全可控，但 y-sort、图集、滤镜、缩放都得自己写 |
| UI 面板 | **DOM／CSS 覆盖在画布上** | Canvas 内自绘 HUD | A 的文本输入、滚动、选区、聊天框、可访问性天然好用；代价是要处理点击穿透与 DPI 对齐。B 更贴原版观感，代价是文本框、滚动条、光标都要自己实现 |
| 语言／构建 | **TypeScript ＋ Vite** | 原生 JS ＋ 无构建 | A 有类型约束，几百条配置表不容易写错；代价是需要构建链。B 双击就能开，代价是项目一大就没有防错 |
| 单机存档 | **IndexedDB** | localStorage | A 能装下物品实例、任务进度、多个存档位；代价是 API 异步。B 简单但容量小、只能存字符串 |

> 四条都选 A 就能直接开工；任何一条改 B，我会同步调整 `_archive/legacy-web-layout/platform/` 的加载与存档层设计。

## 三、分层与模块（已定稿，见架构文档）

```
_archive/legacy-web-layout/client/   →  _archive/legacy-web-layout/domain/  →  _archive/legacy-web-layout/data/        单向依赖，下层绝不反向
   ↑            ↑
_archive/legacy-web-layout/platform/（主循环、加载、事件、日志、构建）
_archive/legacy-web-layout/server/   （本阶段只划边界，不实现）
```

运行时模块 **M1–M10**：成长、战斗、背包装备、世界寻路、任务、社交国家、活动、经济、输入 HUD、状态权威。
其中 **M7 活动** 与 **M8 经济里的商业化部分** 按用户判定裁剪为空。
详见 `docs/architecture/01-模块功能边界.md`。

**三条现在就要定死、否则将来加多人必然返工**：
1. 伤害／掉落／交易／任务进度一律走 `_archive/legacy-web-layout/domain/`，`_archive/legacy-web-layout/client/` 只发意图、只收状态；
2. `M10 state-authority` 是唯一持有游戏状态的地方，将来整体搬去 `_archive/legacy-web-layout/server/` 即可；
3. 客户端不得直接写回「结果性」数值。

## 五、渲染与资源管线

1. `assets/` 放原创重绘源文件 → 构建生成图集与清单 → `_archive/legacy-web-layout/public/` 放浏览器成品。
2. 按场景按需加载 ＋ 进度条（对应原版 SWF 流式加载的体感）。
3. 斜 45° 实体用 **y-sort** 排序，规则写进 `_archive/legacy-web-layout/client/` 并在「像」阶段对着截图验。
4. 逻辑用固定步长 tick，渲染 60／30 帧可调，两者解耦。
5. 8 向序列帧、整套换装（不做分部件叠加）、飞行器载具、6 人组队面板。
6. 地图有边界，触碰传送阵切图；寻路是**单图内 A\***，不做跨图无缝路径。

**版权红线**：考据图一个像素都不进 `assets/`；每个资源登记「来源＝原创重绘」＋「参考编号」；
合入前跑哈希比对。详见 `docs/art/01-资产分区与版权隔离.md`。

## 六、最小可玩闭环（MVP 唯一主干）

```
遗迹之岛(<10级) → 点任务自动寻路 → 点怪 → 1–8 放技能 → 即时结算＋飘字
→ 掉落拾取 → 交任务、升级加点 → 整套换装／套装档 → 传送阵切沐光平原(10级)
→ 生命之境(30级后) → 副本（每天 2 次）
```

任何分支玩法都不能挤掉这条主干。开发顺序 L0–L5 见
`docs/design/01-核心循环与验收基准.md`。

## 七、验收：三阶段，不许跳

| 阶段 | 拿什么验 | 过关条件 |
|---|---|---|
| **像** | 18 张媒体图 ＋ 85 张台服图逐张对照 | 1920×1080 等比缩放后 HUD 位置、斜 45°、2–3 头身、配色、双排 8 格＋7 按钮对得上图；8 向走动、传送阵切图可操作 |
| **准** | 事实基线逐条 | 三国／150／6 职业／转职重置属性点／翅膀外观＋少量属性／副本 2 次／6 人组队／三级货币／非绑定可交易／拍卖行跑通；商业化与活跃度确认不存在 |
| **好玩** | 实机试玩，不看截图 | 自动寻路不卡、战斗不飘、反馈及时、任务链不打断、60／30 帧不撕裂 |

每阶段都保留「能对照某张考据图」的口子 —— 这正是 Q8 要求截图只作验收参照的原因。

## 九、风险清单（按影响排序）

1. **数值几乎全缺**：原版没有可导出的配置表，等级曲线、技能伤害、掉落率、装备逐件属性都没有。
   只能靠用户补或留占位值，这是「准」阶段最大的不确定源。
2. **116 条台账 + 85 张逐图未判定**：不能当作已确认，否则会把猜的东西写进配置。
3. **A2 字体／A5 UI 交互态确实没资料**：按用户判定不猜不编，用自定一致样式并注明「非考据还原」。
4. **A15／A16 二级页面与登录链路缺图**：台服素材只补到部分面板，边角仍缺。
5. **斜 45° 遮挡**：Flash 原图层顺序拿不到，y-sort 需自己定并验收。
6. **台服／大陆版本差异**：已按用户口径统一（简体译名、三国、不参考台服国家名），
   但 V8 国战人数、F12／F13 简写等仍有歧义，落配置前需回看。
7. **「转职」两套口径**：用户说翅膀 3 种，媒体稿说六大二转职业 —— 已按用户口径，
   但实现时若发现与截图冲突，要回来再确认，不擅自折中。
