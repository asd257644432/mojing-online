# 04 · 实机画面风格解剖（用数据说话）

> 结论先行：不是"我画得不好看"，是**尺寸、配色、材质三样都量错了**。
> 下面每个数字都是从截图里量出来的，不是感觉。

## 一、量出来的事实

| 项目 | 实测 | 我此前的做法 | 差在哪 |
|---|---|---|---|
| 快捷格边长 | **44 px**（1606 宽截图里） | 画了 88 px | **大了一倍** |
| 状态条宽度 | 约 150 px | 168 px | 偏大 12% |
| 说明框宽度 | 约 430 px | 620 px | **大了 44%** |
| 正文行高 | **10–12 px** | 13–17 px | 偏大 |
| 主界面平均色 | RGB(112,136,43)，**黄绿** | 橄榄绿偏暗 | 色相偏了 20° |
| 平均饱和度 | **0.75（很高）** | 约 0.5 | 草地不够艳 |
| 低饱和像素占比 | **7%**（只有木/金 UI） | 约 30% | UI 面积占比过大 |
| 主色前五 | `#669410` `#6fa41f` `#96aa3b` `#497b0a` `#b9d26c` | 更暗更灰 | 整体压暗了 |
| 商城图标边框 | 品红 `#b325ca` | 金色 | 高光色用错 |
| 商城面板底 | `#39352a`（暗橄榄棕） | 米黄 | 面板色用错 |
| 描边 | 1 px 深棕，只在暗侧 | 2–3 px 近黑，全包 | 太重太黑 |
| 相邻像素相关性 | 商城面板 0.59（锐）/ 说明框 0.95（糊） | 全部画成锐 | 该糊的地方没糊 |

## 二、这个风格到底是什么

一句话：**1024×600 时代的 Flash 页游，小尺寸、强饱和、轻描边、脏金色。**

拆开看四条：

1. **尺寸小**：所有 UI 元素按 40–60 px 设计，字号 10–12 px。截图看着大，是因为被放大了。
2. **世界艳、UI 脏**：草地是高饱和黄绿，UI 是放了十年的旧黄铜——不是新买的金子。
3. **描边薄**：1 px 深棕，只压暗部。不是黑边，不是双线。
4. **要糊**：小尺寸本来就糊，放大后更糊。我画得太清楚，反而显假。

## 三、为什么之前三轮都不像

| 轮次 | 做法 | 为什么不行 |
|---|---|---|
| R1 矢量 | 88px 格子、黑描边、亮金色 | 尺寸大一号、边太重 |
| R2 笔刷 | 把 88px 的格子加毛边 | 尺寸没改，加质感只是把错的东西画得更细 |
| B 混合 | AI 画人物、程序做框 | 人物对了，框还是 88px，且草地色相仍偏暗 |

**根因只有一个：先定尺寸和色板，再谈画法。** 我顺序反了。

## 四、复刻配方（六条，按顺序执行）

1. **先定基准**：按 1024×600 画，再整体放大 1.875 倍到 1920。禁止直接在 1920 上画细节。
2. **锁死尺寸**：格子 24 px（→45 放大后）、状态条 80×14、说明框 230×160、字号 6–7 px（→11–13）。所有件按同一张尺寸表。
3. **锁死色板**：世界 8 色（黄绿系）＋ UI 6 色（旧铜、暗棕、米黄、品红高光、深棕描边、白字）。超出色板一律不准用。
4. **描边 1 px**：颜色 `#2a1a08`，只画在右下，不包一圈。
5. **一条高光**：金边上沿 1 px `#ffe6a6`，其余位置不准加亮。
6. **最后统一"变糊"**：缩到目标尺寸 → 放大 1.875 倍 → 高斯 0.3 px → 加 5% 噪点。

## 五、验收（三秒法则）

- 把成品缩到 50% 看：还能一眼认出是格子/血条/说明框 → 过。
- 把成品和原作并排：**先看尺寸对不对，再看颜色，最后看细节**。顺序不能反。
- 尺寸差超过 10% 直接打回，不用看细节。

## 六、试点结论（2026-11-06）

按 28px 画格子、24×11 画血条，再放大 1.875 倍，与原作并排：**质感对上了**。
关键不是画法，是「小尺寸直画 → 放大 → 轻微模糊」这一步。放大后的锯齿和柔边，正是原作的样子。
